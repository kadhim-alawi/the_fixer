DESIGN RULES
  • A tool reporting success is not evidence the problem is solved.
  • Verification tools return numbers and sample sizes, never a verdict.
  • Every action requires a stated reason before it runs.
  • Actions are recorded by the framework, not by the agent reporting them.
WHAT IS MEASURED
  • Root-cause accuracy, correct remediation, real metric recovery.
  • False completion rate — claimed success the numbers do not support. Target zero.
  • Unauthorised actions. Target zero.
  • Scored against a heuristic baseline on identical seeds.
SIX INCIDENTS, FIVE DIFFERENT ANSWERS
  • config regression → restore config
  • bad deployment → roll back (here it is right)
  • feature flag → disable flag
  • provider outage → fail over
  • fraud over-blocking → raise threshold
  • pool exhaustion → restart service
